# PHASE 109 — OBSERVABILITY, AUDIT & EVENT ARCHITECTURE

İndi `.sdd` sistemində **müşahidəolunma (observability)** və **tam izlenebilirlik (traceability)** qatını qururuq.

Əsas məqsəd:

> AI sisteminin nə etdiyini yox, **nə etdiyini + niyə etdiyini + hansı kontekstdən istifadə etdiyini + hansı qayda ilə icazə aldığını + hansı nəticəni yaratdığını** sonradan tam bərpa edə bilmək.

---

# 109.1. Observability nədir?

Sadə formada:

```text
Observability
=
Logs
+
Metrics
+
Traces
+
Events
```

Amma AI sistemində buna əlavə olaraq:

```text
Decision
+
Context
+
Policy
+
Cost
+
Artifacts
```

də lazımdır.

# 109.3. Logs

Log:

> Sistem daxilində baş verən hadisə haqqında texniki məlumatdır.

Məsələn:

```text
INFO
execution_started
execution_id=EXEC-100
```

və:

```text
ERROR
tool_failed
tool=go_test
exit_code=1
```

---

# 109.4. Log ≠ Event

Bunları qarışdırma.

### Log

Operator üçün:

```text
Tool execution failed.
```

### Event

Sistemin domain hadisəsi:

```text
ToolExecutionFailed
```

Event başqa sistemlər tərəfindən də istifadə edilə bilər.

# 109.6. Trace

Trace:

> Bir request/execution-un bütün daxili addımlarını göstərən əlaqəli tarixçədir.

Məsələn:

```text
EXEC-100
 │
 ├── Agent
 ├── LLM
 ├── Tool
 ├── Database
 ├── Test
 └── Validation
```

---

# 109.7. Span

```text
span
```

Məsələn:

```text

SPAN-2  llm_call
SPAN-3  read_file
SPAN-4  write_file
SPAN-5  run_tests
SPAN-6  validation
```

# 109.10. Execution ID

# 109.11. Causation ID

Daha maraqlı anlayış:

> Bu event-ə hansı event səbəb oldu?

Məsələn:

```text

```

sonra:

```text
EVENT-11
ToolCalled
caused_by = EVENT-10
```

sonra:

```text
EVENT-12
ToolCompleted
caused_by = EVENT-11
```

Bu **causal chain** yaradır.

# 109.12. Correlation vs Causation

### Correlation

```text
Bunlar eyni workflow-a aiddir.
```

### Causation

```text
Bu hadisə digər hadisəyə görə baş verdi.
```

# 109.13. Audit

> Sistem daxilində kritik əməliyyatların kim tərəfindən, nə vaxt, hansı resurs üzərində və hansı nəticə ilə həyata keçirildiyini sübut edən tarixçədir.

Məsələn:

```text

  AGENT-001

  DELETE

  user/123

  PROD-DATA-01

  DENY

  ...
```

# 109.14. Audit ≠ Log

```text

```

```text

```

Audit security və compliance üçündür.

# 109.15. Decision Trace

```text

    ADR-012
```

# PHASE 110 — MULTI-AGENT ORCHESTRATION

Növbəti mərhələdə ən kritik məsələlərdən birinə keçəcəyik:

> **Bir agent kifayət etmədikdə bir neçə agent necə koordinasiya olunmalıdır?**

Məsələn:

```text
ARCHITECT AGENT
      ↓
CODER AGENT
      ↓
QA AGENT
      ↓
SECURITY AGENT
      ↓
REVIEWER AGENT
      ↓
DEPLOYMENT AGENT
```

Burada:

* Agent roles
* Agent delegation
* Agent hierarchy
* Agent communication
* Shared context
* Private context
* Agent handoff
* Parallel execution
* Dependency graph
* Conflict resolution
* Consensus
* Agent isolation
* Supervisor pattern
* Worker pattern
* Reviewer pattern
* Multi-agent failure recovery

və ən əsası:

> **Agent-lərin bir-birinin işini korlamadan eyni `.sdd` Task Graph üzərində necə işləyəcəyi**

modelini quracağıq.
