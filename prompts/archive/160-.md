# PHASE 101 — SDD COMPILER, VALIDATOR & EXECUTION ENGINE

İndi artıq `.sdd`-nin **real işləyən sistemə necə çevriləcəyini** öyrənirik.

Əvvəlki mərhələdə:

```text
.sdd
 ↓
Desired State
 ↓
Orchestrator
 ↓
Agents
 ↓
Runtime
```

modelini gördük.

İndi sual:

> `.sdd` fayllarını runtime necə oxuyacaq və onların əsasında nə etməli olduğunu necə anlayacaq?

Cavab:

```text
SDD Compiler + Execution Engine
```

---

# 101.1. SDD-ni proqramlaşdırma dili kimi düşün

Məsələn Go kodu:

```text
source code
    ↓
lexer
    ↓
parser
    ↓
AST
    ↓
type checking
    ↓
compiler
    ↓
machine code
```

SDD-də də oxşar pipeline yarada bilərik:

```text
.sdd files
    ↓
parser
    ↓
AST
    ↓
validation
    ↓
graph
    ↓
execution plan
    ↓
runtime
```

Bu çox vacib mental modeldir.

```text

```

```text
Task
├── id: TASK-100
└── requires
    └── SKILL-GO
```

# 101.5. AST nədir?

AST:

> Abstract Syntax Tree

deməkdir.

Yəni `.sdd` mətninin semantic strukturudur.

Məsələn:

```text
Task
 ├── ID
 ├── Dependencies
 ├── Skills
 ├── Agent
 ├── Policies
 └── Outputs
```

Runtime artıq raw text ilə işləmək məcburiyyətində deyil.

---

# 101.6. Niyə AI-yə raw `.sdd` vermək kifayət deyil?

Pis architecture:

```text
.sdd
 ↓
LLM
 ↓
"nə etmək lazımdır?"
```

Problem:

* ambiguity
* inconsistent interpretation
* missing references
* invalid dependencies
* policy bypass
* hallucination

Ona görə deterministic layer lazımdır.

# 101.14. Cycle Detection

Əgər:

```text
A → B
B → C
C → A
```

olarsa:

```text
cycle detected
```

Bu execution üçün problem yaradır.

Compiler bunu runtime-a çatmamış aşkar etməlidir.

---

# 101.15. Topological Sort

Cycle yoxdursa graph:

```text
A → C
B → C
```

üçün:

```text
A
B
C
```

kimi valid execution order yaradıla bilər.

---

# 101.16. Parallelism

A və B bir-birindən asılı deyilsə:

```text
A ──┐
    ├──→ C
B ──┘
```

compiler deyə bilər:

```text
parallel:
  A
  B

then:
  C
```

Bu execution engine-ə optimallaşdırılmış plan verir.

# PHASE 102 — SDD DATA MODEL & GRAPH DATABASE THINKING

Orada `.sdd`-də **Requirement, Domain, Entity, API, Table, Task, Skill, Agent, Decision, Policy, Test və Artifact** arasındakı əlaqələri formal data modelə çevirəcəyik və sualı cavablandıracağıq:

> **`.sdd`-nin arxasında relational database, graph database, yoxsa hybrid model daha doğrudur?**
