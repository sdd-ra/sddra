# PHASE 103 — SDD SKILL SYSTEM & AI EXECUTION PROTOCOL

Bu dərsdə `.sdd` sisteminin **ən vacib komponentlərindən biri olan Skill System**-i formal şəkildə qururuq.

Sənin əvvəlki ideyanın əsas məqsədi budur:

> **AI hər dəfə "nə edim, harada edim, hansı qaydanı oxuyum?" deyə özü axtarmamalıdır. Skill Chain ona bunu əvvəlcədən göstərməlidir.**

---

# 103.1. Skill nədir?

Skill sadəcə:

```text
"Go programming"
```

deyil.

Skill:

> **müəyyən işi müəyyən input və qaydalar əsasında müəyyən output-a çevirən icra edilə bilən capability-dir.**

Məsələn:

```text
SKILL-API-IMPLEMENT
```

deyə bilərik.

Onun işi:

```text
API Specification
        ↓
Implementation
        ↓
Tests
```

ola bilər.

---

# 103.2. Skill ≠ Prompt

Bu fərqi çox ciddi yadda saxla.

Prompt:

```text
"Implement this API in Go."
```

Skill:

```text
SKILL-API-IMPLEMENT

input:
  API specification

requires:
  GO
  REST
  TESTING

must:
  inspect existing architecture
  implement endpoint
  add tests
  validate contract

output:
  implementation
  tests
```

Prompt instruction-dır.

Skill isə **formal execution unit**-dir.

---

# 103.3. Skill ≠ Tool

Tool:

```text
git.commit
```

Skill:

```text
IMPLEMENT-FEATURE
```

Skill tool-lardan istifadə edə bilər.

```text
Skill
 ├── read_file
 ├── edit_file
 ├── run_test
 └── git_diff
```

Deməli:

```text
Skill = What/how workflow

Tool = Capability/action
```

---

# 103.4. Skill ≠ Agent

Agent:

```text
CODER
QA
ARCHITECT
```

Skill:

```text
IMPLEMENT-API
RUN-TESTS
REVIEW-CODE
```

Agent skill-i **icra edir**.

```text
Agent
   ↓
Skill
   ↓
Tools
```

# 103.5. Skill Contract

Hər skill-in contract-ı olmalıdır.

Məsələn:

```text
skill:
  id: SKILL-API-IMPLEMENT

input:
  - API_SPEC

requires:
  - GO
  - REST
  - TESTING

outputs:
  - CODE
  - TEST

must:
  - follow architecture
  - preserve contracts

must_not:
  - modify unrelated domains
```

# 103.11. Chain vs Graph

Chain:

```text
A → B → C → D
```

Graph:

```text
      B
     ↗ ↘
A →       D
     ↘ ↗
      C
```

Graph daha real sistemləri modelləşdirə bilir.

# 103.12. Skill Dependency

Məsələn:

```text

  SKILL-DESIGN
```

Deməli:

```text
IMPLEMENT
```

birbaşa başlaya bilməz.

Əvvəl:

```text
DESIGN
```

---

# 103.13. Skill Gate

Skill-in qarşısında gate ola bilər:

```text
DESIGN
   ↓
[DESIGN APPROVED?]
   ↓ yes
IMPLEMENT
```

Əgər:

```text
approved = false
```

olarsa:

```text
IMPLEMENT = BLOCKED
```

---

# 103.14. Gate ≠ Skill

Gate iş görmür.

Gate yoxlayır:

```text
condition == true?
```

Skill isə action edir.

```text
Gate
 ↓
allow / block

Skill
 ↓
execute
```

# 103.49. Skill Execution Protocol

### Əsas prinsip:

> **Skill AI-yə nəyi etməli olduğunu, Skill Context harada etməli olduğunu, Policy nəyi etməyə icazə verildiyini, Tool isə bunu necə edə biləcəyini müəyyən edir.**

Bu dördünü bir-birinə qarışdırmamaq lazımdır:

```text
Skill  = WHAT
Context = WHERE / WITH WHAT
Policy = WHETHER ALLOWED
Tool   = HOW
```

Növbəti dərsdə bunun üstündə daha fundamental bir qat quracağıq:

# PHASE 104 — SDD TASK ENGINE & TASK DECOMPOSITION

Burada `TASK`-ın necə yaradıldığını araşdıracağıq:

```text
Requirement
 ↓
Feature
 ↓
Epic
 ↓
Task
 ↓
Subtask
 ↓
Skill
 ↓
Execution
```

və xüsusilə **AI böyük bir requirement-i necə düzgün task-lara bölməlidir, task-ların sərhədini kim müəyyən etməlidir, dependency-lər necə yaranmalıdır və "AI taskı özü bölə bilərmi?"** sualını formal architecture səviyyəsində həll edəcəyik.
