# PHASE 108 — EXECUTION ENGINE & STATE MACHINE

İndi `.sdd` sisteminin **real icra qatına** keçirik.

İndiyə qədər:

```text
Requirement
 ↓
Task
 ↓
Agent
 ↓
Skill
 ↓
Context
 ↓
Policy
 ↓
Gate
 ↓
Tool
```

qurmuşuq.

Amma bunların hamısı hələ **plan**dır.

Əsas sual indi budur:

> **Task başlayandan sonra sistem onun vəziyyətini necə idarə edir?**

---

# 108.1. Execution nədir?

Execution:

> Task-ın agent tərəfindən real olaraq icra olunması və bütün state dəyişikliklərinin idarə olunmasıdır.

Məsələn:

```text
TASK-100
```

üçün:

```text
Execution-500
```

yaradılır.

---

# 108.2. Task ≠ Execution

Çox vacib fərq:

```text
Task
```

deyir:

> Nə edilməlidir?

```text
Execution
```

deyir:

> Bu task konkret olaraq nə vaxt və necə icra edildi?

Məsələn:

```text
TASK-100
```

bir neçə dəfə execute oluna bilər:

```text
EXEC-1 → failed
EXEC-2 → retry
EXEC-3 → success
```

---

# 108.3. Execution ID

Hər execution-un unikal ID-si olmalıdır:

```text
EXEC-2026-00125
```

Bu ID bütün event-lərdə istifadə olunur.

```text
Execution
 ├── events
 ├── tool calls
 ├── context snapshot
 ├── policy decisions
 ├── artifacts
 └── errors
```

---

# 108.4. State Machine

Execution sadəcə:

```text
running = true
```

olmalı deyil.

Formal state machine lazımdır.

Məsələn:

```text
PENDING
  ↓
READY
  ↓
RUNNING
  ↓
VALIDATING
  ↓
COMPLETED
```

Failure zamanı:

```text
RUNNING
   ↓
FAILED
   ↓
RETRYING
   ↓
RUNNING
```

# 108.16. State Transition

State dəyişiklikləri sərbəst olmamalıdır.

Məsələn:

```text
PENDING → RUNNING
```

bəzi sistemlərdə düzgün ola bilər.

Amma:

```text
COMPLETED → RUNNING
```

normal flow-da düzgün deyil.

---

# 108.17. Transition Rules

Məsələn:

```text
PENDING → READY
READY → RUNNING
RUNNING → WAITING_APPROVAL
RUNNING → WAITING_INPUT
RUNNING → PAUSED
RUNNING → VALIDATING
RUNNING → FAILED
RUNNING → CANCELLED

VALIDATING → COMPLETED
VALIDATING → FAILED

WAITING_APPROVAL → RUNNING
WAITING_APPROVAL → CANCELLED

PAUSED → RUNNING
```

# 108.45. Compensation

Bəzi action-lar artıq icra olunubsa rollback mümkün olmaya bilər.

Məsələn:

```text
Create Payment
```

edilib.

Sonra:

```text

```

```text
Delete Payment
```

olmaya bilər.

```text
Refund Payment
```

edilə bilər.

Bu:

> **Compensation**

adlanır.

---

# 108.46. Rollback ≠ Compensation

Rollback:

> əvvəlki state-ə qaytarmaq.

Compensation:

> əvvəlki action-un təsirini başqa action ilə kompensasiya etmək.

Distributed systems-də compensation çox vacibdir.
