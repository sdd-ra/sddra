# PHASE 107 — SDD POLICY ENGINE & GOVERNANCE

İndi `.sdd` sisteminin **idarəetmə və təhlükəsizlik qatına** keçirik.

İndiyə qədər agentə deyirdik:

```text
Task → Agent → Skill → Context → Tool
```

Amma bir sual qalır:

> **Agent bunu etməyə həqiqətən icazəlidirmi?**

Məsələn agent:

```text
DELETE production database
```

əmrini icra etməyə texniki olaraq qadir ola bilər.

Amma **capability ≠ permission**.

---

# 107.1. Governance nədir?

Governance:

> AI agentlərin nə edə biləcəyini, hansı şərtlərdə edə biləcəyini və hansı hallarda insan təsdiqinin tələb olunduğunu müəyyən edən idarəetmə sistemidir.

Sadə model:

```text
Capability
    ≠
Permission
    ≠
Policy
```

---

# 107.2. Capability

Capability:

> Agent bunu bacarırmı?

```text
AGENT-CODER
    ↓
CAN:
  GO
  PostgreSQL
  REST
```

---

# 107.3. Permission

Permission:

> Agent bunu etməyə icazəlidirmi?

```text
CAN:
  read source

  write production
```

# 107.4. Policy

Policy:

> Hansı şəraitdə hansı action-a icazə verilir?

Məsələn:

```text
Production database migration
→ only DevOps agent
→ requires approval
→ backup must exist
```

Bu artıq policy-dir.

# 107.13. Decision Types


---

# 107.14. Policy Evaluation

Conceptual:

```text
evaluate(request):

  policies = resolve(request)

  for policy in policies:
      result = evaluate(policy, request)

      if result == DENY:
          return DENY

      if result == REQUIRE_APPROVAL:
          return REQUIRE_APPROVAL

  return ALLOW
```

Amma real sistemdə conflict resolution ayrıca qayda tələb edir.

# 107.16. Deny by Default

> **Explicitly allowed olmayan action default olaraq DENY olmalıdır.**

# 107.32. Policy ≠ Validation

Validation:

> nəticə düzgündürmü?

Policy:

> bunu etməyə icazə varmı?

Məsələn:

```text
Code compiles
```

→ validation.

```text
Agent can modify this file
```

→ policy.

# 107.33. Policy ≠ Test

```text

→ 200
```

```text

```

Bunlar fərqli qatdır.
