# PHASE 131 — `TASK GRAPH & AUTONOMOUS EXECUTION PLANNER`

Bu mərhələdə `.sdd` artıq sadəcə **"AI nə bilməlidir?"** sualını yox, **"AI böyük işi hansı ardıcıllıqla, hansı asılılıqlarla və hansı təhlükəsizlik sərhədləri daxilində görməlidir?"** sualını həll edir.

Əsas prinsip:

> **Task list ≠ Task Graph.**

---

# 1. Sadə task list kifayət deyil

Məsələn:

```text
TASK-1001 Create database tables
TASK-1002 Create API
TASK-1003 Create service
TASK-1004 Add tests
TASK-1005 Add documentation
```

Bu sadəcə siyahıdır.

AI bilmir:

```text
1002 → 1001-dən asılıdır?
1004 → API-dən sonra olmalıdır?
1003 və 1001 paralel gedə bilər?
```

# 56. Növbəti mərhələ

İndi sistem artıq task-ları planlaya və execute edə bilir.

Amma bir problem qalır:

> **AI nə qədər yaxşı plan qursa da, eyni project-də bir neçə AI agent eyni anda işləsə nə olacaq?**

Məsələn:

```text
Agent A → payment
Agent B → balance
Agent C → documentation
Agent D → tests
```

və hamısı eyni `.sdd`, kod, knowledge və decision graph-a toxunur.

Burada:

* ownership
* locks
* leases
* agent coordination
* shared state
* conflict resolution
* handoff
* agent roles
* concurrent execution
* merge strategy

lazım olacaq.

Ona görə növbəti:

# **PHASE 132 — `MULTI-AGENT COORDINATION & SHARED ENGINEERING STATE`**

Burada artıq `.sdd`-ni tək AI üçün yox, **bir neçə AI agent + human developer komandasının ortaq engineering brain-i** kimi quracağıq.

Əsas fikir:

> **Agentlər bir-birinin context-ini kopyalamamalıdır; hamısı eyni `.sdd` truth/state sisteminin müxtəlif "işçiləri" olmalıdır.**
