# PHASE 129 — `ENGINEERING PROOF & VERIFICATION SYSTEM`

Bu mərhələ `.sdd` sistemində **"iş görüldü" ilə "işin düzgün görüldüyü sübut edildi"** arasındakı fərqi həll edir.

Əsas prinsip:

> **`DONE` bir status deyil, sübutla qazanılan nəticədir.**

AI:

```text
Task completed.
```

deməməlidir.

Əvəzində:

```text
Task completed.

Proof:
    requirement satisfied
    tests passed
    architecture valid
    policies satisfied
    review passed
    documentation updated
```

deməlidir.

---

# 1. `Requirement → Proof`

Hər task requirement-lərə parçalanır.

Məsələn:

```text
TASK-2041

R001:
Refund endpoint must exist.

R002:
Refund must be idempotent.

R003:
Balance must remain consistent.

R004:
Unauthorized users cannot refund.
```

Sonra hər requirement üçün proof tələb olunur.

---

# 2. `Claim`

AI implementation zamanı iddia yaradır:

```text
C001:
Refund endpoint is implemented.

C002:
Duplicate refund requests are prevented.

C003:
Balance update is atomic.

C004:
Authorization is enforced.
```

Amma claim ≠ proof.
